**Lesson from round 6:** most of what is left in `a11y_text` is Word, not
us. Word's export splits a table row broken across pages into two TRs and a
footnote continued on the next page into two Ps; in 17 of the 90 fixtures
with lists it leaves some Lbl empty and moves the label into LBody, or drops
the number altogether (transition_to_work loses "1.1", "2.3", …); CJK
labels split after the first character ("1" | "、"). We keep one TR per row,
one P per note and the whole label in Lbl. Neutralise those before reading a
low score (fold Lbl into LBody, ignore whitespace) — the session's
`fairtext.py` did this; it is cheap to rebuild from `tests/common/a11y.rs`.

**Lesson from round 5:** `/ActualText` on a *structure element* only helps
readers that walk the tag tree (Acrobat, NVDA/JAWS through Acrobat). Text
extraction, search, copy, and Poppler (Evince, Okular, `pdftotext`, our
harness) read the page content and ignore it, and Poppler ignores
`/ActualText` on marked content that draws no glyphs. Prefer fixes in the
content itself: artifacts for decorative copies, invisible text for outlines,
real space glyphs at word boundaries. (The caps Spans still rely on
element-level `/ActualText`; their letters are the same, only the case
differs.)

## Goal

Our PDFs should be **accessible on their own merits**: tagged structure, a
correct reading order, language, metadata and alt text, so that a screen-reader
user gets the whole document and it passes PDF/UA machine checks. Word's own
export is a **floor**, not the yardstick, and where we can do better than Word
we do (line numbers are artifacts, where Word reads them as text; three-level
tables keep their innermost table, where Word flattens it).

**Source-limited failures are expected.** When a check fails because the DOCX
lacks the data (no core-properties title → 7.1-9, a picture with no
`docPr@descr` → 7.3-1, headings that skip a level → 7.4.2-1) we leave it: no
titles from file names, no "Picture 1" alt, no renumbered headings. The
baselines absorb these.

Constraint that stays: **no bloat**. Output size is measured on every change
(but see "Deterministic output" below).

## How it is measured

See `SCORING.md` for every score. `./tools/run-tests.sh --test
accessibility` (needs `brew install verapdf poppler`; veraPDF won't start
inside the Bash sandbox). Code: `tests/accessibility.rs`, `tests/common/a11y.rs`.
Per fixture it records `ua_fail` (all fixtures), `ua_deficit`, `a11y_struct` and
`a11y_text` (tagged references only) into `latest_scores.json`, writes
`generated.deficit.json` (failing rules with check counts) and caches analyses
as `*.a11y.json` (delete them after upgrading veraPDF/Poppler).
`DOCXSIDE_A11Y_GEN=libreoffice.pdf` scores another engine's PDF the same way.

Baselines for all four are in `tests/baselines.json` (round 2 accepted in
`d896900d`); accept only with the user's approval.

The Word-relative metrics can't reward doing better than Word (line numbers,
kept nested tables); `ua_fail` is the absolute arbiter.

## Gaps, in priority order

1. **Math speech** covers the corpus (one fixture): fractions, radicals,
   scripts, delimiters, n-ary operators, Greek, the common operators.
   Matrices, accents, bars and equation arrays are read as their contents in
   order; Word's ClearSpeak says more ("the fraction with numerator …") for
   nested structures.
2. Floating pictures in table cells stay artifacts; header/footer content is
   pagination (Word too).
3. Link rects / outline destinations ignore the comment-pane scale and vAlign
   offset (no fixture has links with either).
4. **Missing non-space glyphs** still draw `.notdef` (none in the corpus):
   Word rescues them per character from another font at their real width;
   widen the CJK rescue (`missing_cjk_chars`) to all characters. The space
   fallback also lays en/em/thin spaces out at U+0020's width.
5. **Text fidelity:** Wingdings 2 and Webdings extract as private-use code
   points (no fixture draws them). (`w:softHyphen` dropped and `w:noBreakHyphen` → U+002D both match
   Word.)
6. **Hoist order** (decided, not a gap): Word orders floats anchored in one
   paragraph by z-order (top first), ties by `docPr/@id`: that fits all 11
   multi-float paragraphs in the tagged references, where XML order fits the
   7 real ones (written in z-order) but not case43/44 (equal z-order). We keep
   XML order, which in case43/44 is also top-to-bottom on the page, a better
   reading order than Word's.
7. **Language:** `w:lang/@bidi` is ignored (no RTL tagging yet), and a
   paragraph wholly in another language could carry `/Lang` on its P instead
   of a Span.
8. **Hoist order across passes:** textboxes from paragraph-level `mc:Choice`
   sort after run-level anchors; the anchor node's XML position would fix it.
9. **Table model:** slovak_eu_directive renders 9 rows where Word has 14.
10. **Harness:** content coverage and reading order against the DOCX (no
    reference needed), the WCAG machine profile; `tests/text_boundary.rs` has
    no `#[test]` since fb9373b; gap scripts (`tag_gaps.py`, `text_gaps.py`)
    lived in a session scratchpad, not `tools/`.

## What Word does (verified against the references)

Useful when choosing a structure; none of this is guessable from the spec.
Copy it only where it isn't worse.

- **Pictures, charts, SmartArt:** an empty P for the paragraph mark, then a
  Figure hoisted to Document level. Floating pictures and textboxes likewise
  follow their anchor P (`Sect > P` for a textbox), in the anchors' XML order.
  Chart and SmartArt Figures expose no text; SmartArt `/Alt` = node texts one
  per line plus "(Layout Name)". Pictures with no `descr` are Figures without
  alt.
- **Tables:** `tblLook` firstRow → THead/TH (on when `tblLook` is absent),
  firstColumn → TH — mostly: the online export gave education_consultant's
  second table (firstRow 0) a THead, and none to tables whose first row
  repeats (`w:tblHeader`, turkish_*). We keep firstRow or tblHeader → THead; header-only tables get an empty TBody; a vMerge
  continuation is an empty cell (no RowSpan); no ColSpan or Scope. Nested
  tables sit inside the cell, with TR directly under Table; a third level is
  flattened to P. Word also flattens some bordered data tables into plain P
  (who_prescribing 16×7, bush_fires 56×4, covid_insomnia).
- **Lists:** a sub-list's L sits inside the parent item's LBody. Some
  documents get an empty Lbl with the label inside LBody, or lose the label
  (see the round 6 lesson).
- **Objects:** an OLE object (`w:object`) is a `Sect` inside its paragraph's
  element with the VML `alt` as `/Alt`, or a blank one. A textbox in a table
  cell is `Sect > P` inside the TD/TH after its anchor paragraph. Header and
  footer textboxes are not tagged.
- **Math:** each zone is a `Formula` inside the P with a spoken `/Alt`;
  its glyphs are Spans inside it.
- **TOC:** TOC/TOCI only inside a real TOC field; each TOCI's Link is the
  `PAGEREF \h` page number.
- **Footnotes:** `P > Link > (OBJR, mark, Footnote > P)`.
- **Text:** tabs and `w:br` extract as spaces; Symbol-font bullets map to
  Unicode; Wingdings extracts inconsistently, as the raw private-use code
  (irish_school, CV, old_blue_truck) or as Unicode (samtale ☺,
  french_sexual_health ➔, indigenous_innovation ✓); line numbers are read as
  text. (macOS print-path references extract the code's low byte, ✔ as "ü".)
- **Language:** catalog `/Lang` is always `en`; the real language is on the
  Span `/Lang` of each run.
- **Marked content never changes inside a text object.**
- **References:** since the 2026-10-03 re-exports 240 of 244 are tagged
  online exports; the 4 others (door_air_cooling among them) are scored by
  `ua_fail` only.

## Working notes

- **Measuring a change:** run the full suite, then compare
  `tests/output/latest_scores.json` with a snapshot from before the change,
  check visual hashes are unchanged (tagging never moves a pixel) and that
  marked content is balanced (a BMC/BDC/EMC nesting check over all PDFs).
- **Deterministic output** (`6f64723a`): the same binary gives the same bytes,
  so size deltas are exact and an unchanged PDF is reused by the harness.
  Any new `HashMap`/`HashSet` iteration that reaches the PDF must sort.
- **One commit per fix:** keep the next fix out of files the pending commit
  touches; edit only after the suite's test binaries are built, and never
  compile test targets while a suite is running (cargo would swap the
  binaries it hasn't run yet).
- **Slow suites:** Microsoft Defender scans `tests/output`, and other sessions
  run suites in `.worktrees/*`; full runs took 9 to 60+ minutes.
- **CLI checks** need `DOCXSIDE_FONTS=$PWD/fonts`, or fonts fall back and
  sizes and structure differ from the harness's output.
